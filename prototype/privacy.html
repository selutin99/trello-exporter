Prototype data handling / Обработка данных прототипом

Updated / Обновлено: 2026-10-18

English

This notice describes the development compatibility prototype, not a released backup service. Use synthetic test data.

The current interface can request the selected test board's ID, name, short link, and archived state directly from the Trello REST API. It does not enumerate other boards, request member profiles, or perform API writes.

The project operates no backend that receives board data, files, or tokens. Selected files are read locally in chunks and are not uploaded. Optional downloaded diagnostics contain the selected board metadata, test file names and sizes, timestamps, and result codes. These files remain under your control; do not publish private diagnostic reports.

OAuth is handled by Atlassian's Power-Up SDK. Its tokens are kept in Trello private plugin data and used in Authorization headers to Trello. They are not included in reports or application logs. Power-Up OAuth permissions include board read/write access within the authorized workspace even though this prototype interface disables writes.

The interface may remember a language preference in local browser storage. Closing the page discards the in-memory diagnostic session. Deleting local site data removes that preference but does not revoke OAuth access.

The static interface is hosted on GitHub Pages and loads the SDK from Atlassian's CDN. Those providers receive ordinary network request metadata under their own policies. The project adds no analytics or advertising scripts.

Use Atlassian connected apps to manage or revoke this app's access. Disabling a Power-Up and deleting local files are separate actions.

Support: GitHub Issues. Use synthetic examples and omit tokens and private data. This notice and the Trello data-storage declaration must be reviewed before introducing full snapshots or any server-side storage.

Русский

Описание относится к техническому прототипу, а не выпущенному сервису резервного копирования. Используйте синтетические тестовые данные.

Текущий интерфейс может получить через Trello REST API ID, название, короткую ссылку и признак архива выбранной тестовой доски. Он не перечисляет другие доски, не запрашивает профили участников и не выполняет запись через API.

У проекта нет сервера, который принимает содержимое досок, файлы или токены. Выбранные файлы читаются частями на устройстве и не загружаются на сервер. Скачиваемая по желанию диагностика содержит метаданные выбранной доски, имена и размеры тестовых файлов, время и коды результатов. Этими файлами управляете вы; не публикуйте отчёты с личными данными.

OAuth обслуживает Power-Up SDK Atlassian. Токены хранятся в приватных plugin data Trello и передаются в заголовках Authorization при обращении к Trello. В отчёты и журналы приложения они не включаются. OAuth для Power-Up выдаёт права чтения и записи досок в авторизованном Workspace, хотя интерфейс этого прототипа запись отключает.

Интерфейс может запомнить выбранный язык в локальном хранилище браузера. Закрытие страницы удаляет диагностическую сессию из памяти. Очистка локальных данных сайта удаляет выбор языка, но не отзывает OAuth-доступ.

Статический интерфейс размещён на GitHub Pages и загружает SDK из CDN Atlassian. Провайдеры получают обычные технические сведения о сетевых запросах согласно своим политикам. Аналитические и рекламные скрипты проект не добавляет.

Управление и отзыв разрешения доступны в разделе подключённых приложений Atlassian. Отключение Power-Up и удаление локальных файлов — отдельные действия.

Поддержка: GitHub Issues. Прикладывайте синтетические примеры без токенов и личных данных. Перед добавлением полного экспорта или серверного хранения это описание и декларацию хранения данных в Trello необходимо пересмотреть.
